# Windows 发行验收

自动化作业可以启动已发布的 `Mote.Windows.exe`、确认第二个实例不会留下来，并在结束后清掉进程。下面这些要在真实的 Windows 桌面上对 **发布产物** 做，不要对 `dotnet run` 的开发构建做。CI 不执行会锁屏、断网或休眠的项目。

标记为手动的项没有自动结果。

| 项 | 方式 |
| --- | --- |
| 启动发布出的 `Mote.Windows.exe` | 手动 |
| 只有一个托盘图标 | 手动 |
| 设置窗口能打开 | 手动 |
| 关掉设置后托盘还在 | 手动 |
| Open Mote 会把设置窗口带回前面 | 手动 |
| 再启动一次不会出现第二个托盘 | 手动。自动化只检查第二个进程会退出 |
| `--background` 不打开设置 | 手动 |
| Quit 去掉托盘并结束进程 | 手动 |
| 可执行文件图标是预期的 Mote 图标 | 手动。正式图标还没有放进工程 |
| 配对 | 手动 |
| Connect | 手动 |
| Disconnect | 手动 |
| 断网后的恢复 | 手动。不要写进 CI |
| 真实休眠 / 唤醒 | 手动。不要写进 CI |
| 登录启动指向这份 `Mote.Windows.exe`，并且带 `--background` | 手动 |
| 凭据恢复 | 手动 |
| 远程锁屏 | 手动，而且必须是有意做的一次。不要写进 CI |

发布工程本身不要求在 CI 里真的锁屏。
